## GA Evidence Adapter Handoff

Current GA state already has a basic OpenClaw adapter path:

- `src/harness/windows.ts` imports `doctorCommand` and `smokeCommand` from `agent-windows-reliability`.
- `src/adapters/openclaw/adapter.ts` runs smoke targets and stores the last harness result.
- `src/harness/mapper.ts` maps harness checks into GA `TaskResult` and `EvidenceBundle`.

Recommended GA-side work for criterion #5:

1. Add an integration/E2E test that executes `OpenClawAdapter` against at least one new OWSL Phase 2 target:
   - preferred: `agent-responsiveness`
   - alternative: `process-tree`
2. Verify the end-to-end path:
   - `executeTask()`
   - `collectEvidence()`
   - evidence bundle creation
   - evidence validation/redaction boundary
3. Assert that harness artifacts remain `redacted: false` and evidence redaction metadata remains unchecked until GA redaction runs.
4. Add a lightweight import contract test from `agent-windows-reliability/schemas`:
   - `AgentWindowsReliabilitySchemas.HarnessResultSchema`
   - `AgentWindowsReliabilitySchemas.EvidenceBundleSchema`
   - `AgentWindowsReliabilitySchemas.RuntimeProfileSchema`
5. Keep this as an internal integration test. Do not connect to real customer platform APIs.
