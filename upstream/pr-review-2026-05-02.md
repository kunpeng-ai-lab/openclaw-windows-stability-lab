## PR #73533: Windows tmp directory fix (#60713)

Author: juan-flores077
Status: Open
Branch: `pr-73533`

### Changes

**Commit 5370c6f2a**: Skip POSIX /tmp preferred path on Windows
- File: `src/infra/tmp-openclaw-dir.ts`
- On Windows, Node resolves POSIX `/tmp` to `C:\tmp` (relative to current drive root)
- Git/MSYS2 often create `C:\tmp`, so existing logic writes to `C:\tmp\openclaw\` while everything else expects `%TEMP%\openclaw\`
- Fix: Skip POSIX preferred path entirely on Windows, fall through to `os.tmpdir()` fallback
- Added `platform` option for test seam

**Commit 4cea092df**: Use platform-specific path joiner for tmp fallback
- File: `src/infra/tmp-openclaw-dir.ts`
- Uses `path.win32.join` when platform is `win32` to ensure pure backslash form
- Handles case where tests inject `platform: "win32"` on a Linux runner

### Test Coverage

- `src/infra/tmp-openclaw-dir.test.ts`: 49 new lines of tests
- `extensions/whatsapp/src/media.test.ts`: 6 lines updated

### Assessment

This PR correctly addresses the Windows tmp directory issue. The fix is clean and well-tested.

**Recommendation**: Approve - this PR is ready for merge.

## PR #75343: Windows .cmd shim resolution in LSP (#75352)

Author: Elliot Drel
Status: Open
Branch: `pr-75343`

### Changes

**Commit faf62d5c5**: Resolve Windows .cmd shims in spawnLspServerProcess
- File: `src/agents/pi-bundle-lsp-runtime.ts`
- On Windows, `child_process.spawn()` without `shell:true` cannot find/execute .cmd wrapper scripts
- Causes LSP plugin servers (e.g. typescript-lsp) to fail with ENOENT
- Uses existing `resolveWindowsSpawnProgram()` utility (already used for Docker and memory-host spawning)
- Wires up the utility in `spawnLspServerProcess()` so all LSP servers resolve correctly on Windows

### Code Pattern

```typescript
// Before:
return spawn(config.command, config.args ?? [], { ... });

// After:
const program = resolveWindowsSpawnProgram({
  command: config.command,
  allowShellFallback: true,
});
const invocation = materializeWindowsSpawnProgram(program, config.args ?? []);
return spawn(invocation.command, invocation.argv, {
  ...,
  windowsHide: invocation.windowsHide ?? process.platform === "win32",
  shell: invocation.shell,
});
```

### Assessment

This PR correctly applies the existing Windows spawn utility to LSP server spawning. The pattern is consistent with how Docker and memory-host spawning already work.

**Recommendation**: Approve - this PR is ready for merge.
